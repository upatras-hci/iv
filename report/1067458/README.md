## Introduction

Ονομάζομαι <b>Στεφανίδης Μάριος</b> και είμαι απόφοιτος του Τμήματος Μηχανικών Ηλεκτρονικών Υπολογιστών και Πληροφορικής του Πανεπιστημίου Πατρών (CEID). Τα τελευταία 2,5 χρόνια εργάζομαι ως Software Engineer σε ιδιωτική εταιρεία, ενώ το τελευταίο διάστημα έχω αναλάβει ρόλο Lead Frontend Engineer σε ένα enterprise-scale project. Μέσα από την εμπειρία μου στον σχεδιασμό και την ανάπτυξη διεπαφών χρήστη, συνειδητοποίησα πόσο καθοριστική αποτελεί η αλληλεπίδραση του ανθρώπου με την τεχνολογία – όχι μόνο σε επίπεδο λειτουργικότητας, αλλά και εμπειρίας, συναισθήματος και γνωστικής προσπάθειας.

Η απόφασή μου να παρακολουθήσω το Μεταπτυχιακό στη <b>Διάδραση Ανθρώπου–Υπολογιστή (HCI)</b> προέκυψε τόσο από επαγγελματικά κίνητρα, όσο και από προσωπικό ενδιαφέρον. Αφενός, θέλω να εξελιχθώ πάνω στο αντικείμενο του frontend engineering και του UI/UX (User Interface/User Experience), διευρύνοντας τα hard skills μου αλλά και αποκτώντας βαθύτερη κατανόηση των αρχών που καθορίζουν μια καλή εμπειρία χρήστη. Αφετέρου, πάντα με ενδιέφερε ο τρόπος που λειτουργεί ο ανθρώπινος νους – πώς αντιλαμβανόμαστε, θυμόμαστε, αποφασίζουμε και αλληλεπιδρούμε με το περιβάλλον μας. Ο συνδυασμός τεχνολογίας, γνωσιακής ψυχολογίας και έρευνας που προσφέρει το HCI, καθιστά το τελευταίο το πιο ταιριαστό πεδίο για την εξέλιξή μου.

#### Τι είναι ο άνθρωπος;

Ο άνθρωπος είναι ένα ον που σκέφτεται, αισθάνεται και δημιουργεί. Προσπαθεί να κατανοήσει τον κόσμο γύρω του και να του δώσει νόημα μέσα από τη γνώση, τη δράση και τη σχέση του με τους άλλους.

#### Τι είναι ο υπολογιστής;

Ο υπολογιστής είναι μια συσκευή που δέχεται πληροφορίες, τις επεξεργάζεται και παράγει αποτελέσματα. Αποτελείται από δύο κύρια μέρη: το hardware, δηλαδή τα φυσικά μέρη του (όπως ο επεξεργαστής, η μνήμη και οι συσκευές εισόδου/εξόδου), και το software, δηλαδή τα προγράμματα που καθοδηγούν τον υπολογιστή πώς να εκτελεί τις εργασίες του.

#### Τι είναι η διάδραση ανθρώπου-υπολογιστή

Η διάδραση ανθρώπου–υπολογιστή (Human–Computer Interaction, HCI) είναι η μελέτη και ο σχεδιασμός του τρόπου με τον οποίο οι άνθρωποι χρησιμοποιούν και επικοινωνούν με τους υπολογιστές και τα ψηφιακά συστήματα. Στόχος της είναι να καταστήσει τη χρήση των υπολογιστών εύκολη, αποδοτική και παράλληλα ευχάριστη για τον άνθρωπο.

#### Ποια είναι μια αναλογία για τον υπολογιστή πέρα από εργαλείο;

Ο υπολογιστής είναι σαν ένας συνεργάτης που ακολουθεί τις οδηγίες σου, επεξεργάζεται μεγάλες ποσότητες πληροφοριών και σε βοηθά να ολοκληρώνεις σύνθετες εργασίες πιο γρήγορα, αποτελεσματικά και με μεγαλύτερη ακρίβεια.

## Γραμμή Εντολών (Arch Linux)

Asciinema link: https://asciinema.org/a/jWhEtznf8YjU4ADmGQlJm7kGG

Για την εγκατάσταση Arch Linux σε VMWare ακολούθησα τα παρακάτω βήματα:

- Boot από το Arch Linux ISO

  ```
  # Έλεγχος σύνδεσης δικτύου
  ping -c 3 archlinux.org

  # Συγχρονισμός ρολογιού συστήματος
  timedatectl set-ntp true
  ```

- Διαμόρφωση Δίσκου

  ```
  # Προβολή διαθέσιμων δίσκων
  fdisk -l

  # Δημιουργία partitions
  fdisk /dev/sda
  ```

  Εντός του fdisk

  1. g - Δημιουργία νέου GPT partition table
  2. n - Νέο partition για EFI (π.χ. 512M)
  3. t - Αλλαγή τύπου σε EFI System (1)
  4. n - Νέο partition για root (υπόλοιπος χώρος)
  5. w - Αποθήκευση

  ```
  # Format partitions
  mkfs.fat -F32 /dev/sda1 # EFI partition
  mkfs.ext4 /dev/sda2 # Root partition

  # Mount filesystems
  mount /dev/sda2 /mnt
  mkdir -p /mnt/boot
  mount /dev/sda1 /mnt/boot
  ```

- Εγκατάσταση Βασικού Συστήματος

  ```
  # Εγκατάσταση βασικών πακέτων
  pacstrap /mnt base linux linux-firmware
  ```

- Διαμόρφωση Συστήματος

  ```
  # Δημιουργία fstab
  genfstab -U /mnt >> /mnt/etc/fstab

  # Chroot στο νέο σύστημα
  arch-chroot /mnt
  ```

- Ρυθμίσεις Βασικού Συστήματος

  ```
  # Ορισμός timezone
  ln -sf /usr/share/zoneinfo/Europe/Athens /etc/localtime
  hwclock --systohc

  # Εγκατάσταση απαραίτητων πακέτων
  pacman -S nano vim networkmanager grub efibootmgr

  # Διαμόρφωση locale
  nano /etc/locale.gen

  locale-gen

  echo "LANG=en_US.UTF-8" > /etc/locale.conf

  # Ορισμός hostname
  echo "1067458" > /etc/hostname

  # Διαμόρφωση /etc/hosts
  nano /etc/hosts
  ```

  Περιέχομενο /etc/hosts:

  ```
  127.0.0.1   localhost
  ::1         localhost
  127.0.1.1   1067458.localdomain 1067458
  ```

- Χρήστες και Κωδικοί

  ```
  # Ορισμός κωδικού root
  passwd

  # Δημιουργία χρήστη
  useradd -m -G wheel -s /bin/bash <username>
  passwd <username>

  # Ενεργοποίηση sudo για wheel group
  EDITOR=nano visudo
  ```

- Εγκατάσταση Bootloader

  ```
  # Εγκατάσταση GRUB για UEFI
  grub-install --target=x86_64-efi --efi-directory=/boot --bootloader-id=GRUB

  # Δημιουργία GRUB configuration
  grub-mkconfig -o /boot/grub/grub.cfg
  ```

- Ενεργοποίηση Υπηρεσιών

  ```
  # Ενεργοποίηση NetworkManager
  systemctl enable NetworkMamager
  ```

- Ολοκλήρωση Εγκατάστασης

  ```
  # Έξοδος από chroot
  exit

  # Unmount partitions
  unmount -R /mnt

  # Επανεκκίνηση
  reboot
  ```

Μετά την ολοκλήρωση της εγκατάστασης εκτέλεσα τις εξής εντολής προκειμένου να δημιουργήσω τα παραδοτέα της άσκησης και το ζητούμενο [recording](https://asciinema.org/a/jWhEtznf8YjU4ADmGQlJm7kGG).

```

pacman -Syu

# Εγκατάσταση του asciinema για καταγραφή terminal sessions
pacman -S asciinema

# Εγκατάσταση του fastfetch για εμφάνιση πληροφοριών συστήματος
pacman -S fastfetch
```

- <b>[Nintendo Power Glove (1989):](https://hci-iv-2025.netlify.app/figure/nes-power-glove/)</b> Το γάντι που ήθελε να γίνει το μέλλον — και απέτυχε θεαματικά

![Power Glove](https://upload.wikimedia.org/wikipedia/commons/d/d3/NES-Power-Glove.jpg)

Το Power Glove κυκλοφόρησε το 1989 από τη Mattel για το Nintendo Entertainment System, βασισμένο στην τεχνολογία του VPL DataGlove των $10,000. Χρησιμοποιούσε οπτικές ίνες στα δάχτυλα που ανιχνεύαν τέσσερις θέσεις ανά δάχτυλο, αλλά η ακρίβειά του ήταν εξαιρετικά χαμηλή. Παρά τις περίπου ένα εκατομμύριο πωλήσεις, το προϊόν απέτυχε λόγω των εξαιρετικά δύσχρηστων χειριστηρίων. Εξετάζει πώς το "too early" φαινόμενο και η φτηνή υλοποίηση μιας καινοτόμου ιδέας μπορεί να καταστρέψει την υπόσχεση της.

- <b>[Light Pen (1950s-1980s):](https://hci-iv-2025.netlify.app/figure/light-pen/)</b> Το πρώτο touchscreen που κούραζε τα χέρια μας

![Light Pen](https://upload.wikimedia.org/wikipedia/commons/c/cd/HypertextEditingSystemConsoleBrownUniv1969.jpg)

Το light pen δημιουργήθηκε γύρω στο 1951-1955 ως μέρος του έργου Whirlwind I στο MIT και χρησιμοποιήθηκε στο σύστημα SAGE για στρατιωτική επιτήρηση του εναέριου χώρου. Στη δεκαετία του 1960, τα light pens ήταν συνηθισμένα σε γραφικά τερματικά όπως το IBM 2250. Ωστόσο, επειδή ο χρήστης έπρεπε να κρατά το χέρι του μπροστά στην οθόνη για μεγάλα χρονικά διαστήματα (προκαλώντας "gorilla arm"), το light pen έπεσε σε αχρησία. Η ιδέα παρουσιάζει πώς η εργονομία είναι εξίσου σημαντική με την τεχνολογική καινοτομία.

## Γραμμή εντολών (Custom Desktop Environment)

Στο [discussion](https://github.com/upatras-hci/iv/discussions/244) μέσω των gif φαίνεται πως έγινε customize το environment.

Αρχικά, ολοκλήρωσα την εγκατάσταση του i3 εκτελώντας τις ακόλουθες εντολές

```bash
# Ενημέρωση Συστήματος
pacman -Syu

# Εγκατάσταση i3
pacman -S i3-wm i3status i3lock dmenu
```

Το i3-wm είναι ο window manager, το i3status για το status bar, το i3lock για το screen locking, και το dmenu για launcher εφαρμογών.

Έπειτα, εγκατέστησα τα εξής:

1. X Server

```bash
pacman -S xorg-server xorg-xinit
```

2. Terminal Emulator

```bash
pacman -S alacritty
```

και προχώρησα με τις κατάλληλες ρυθμίσεις ώστε να ξεκινάει το i3

```bash
echo "exec i3" > ~/.xinitrc
```

#### Προσαρμογες στο i3

- Προσθήκες και αλλαγές στο <b>~/.config/i3/config</b>

  ```bash
  # Όρισα το terminal
  set $term alacritty
  bindsym $mod+Return exec $term

  # Πρόσθεσα launcher rofi)
  bindsym $mod+d exec rofi -show drun
  ```

- Εγκατάσταση <b>i3blocks</b> για καλύτερο status bar

  ```bash
  pacman -S i3blocks

  # Δημιούργησα config για i3blocks
  mkdir -p ~/.config/i3blocks
  cp /etc/i3blocks.conf ~/.config/i3blocks/config
  ```

  - Ενεργοποίηση i3blocks στο i3 config (~/.config/i3/config) και αλλαγή της γραμμής "bar {" με

    ```bash
    bar {
      status_command i3blocks
    }
    ```

## Βιογραφικό Β

[github repo](https://github.com/mstephanidhs/mstephanidhs.github.io)

Σχετικά με το παραδοτέο Β υλοποιήθηκε μια διαδικασία πλήρους Continuous Integration (CI) που παράγει αυτόματα ένα εκτυπώσιμο PDF A4 του βιογραφικού, κάθε φορά που αλλάζουν τα δεδομένα της ιστοσελίδας.

- Παραγωγή του PDF με wkhtmltopdf

  Η ιστοσελίδα του βιογραφικού μου βασίζεται στο Jekyll, επομένως δημιουργήθηκε μία ειδική σελίδα (/print), η οποία περιέχει την εκτυπώσιμη μορφή του CV. Το εργαλείο wkhtmltopdf χρησιμοποιείται για να μετατρέπει το τελικό HTML της σελίδας σε PDF Α4. Η εντολή που χρησιμοποιείται στο CI είναι:

  ```
  wkhtmltopdf -s A4 https://<username>.github.io/print assets/cv.pdf
  ```

  Κατά αυτόν τον τρόπο, το PDF παράγεται πάντα από την τελευταία δημοσιευμένη έκδοση της σελίδας.

- Αυτόματο build και deploy του Github Pages

  Το Github Pages χτίζει αυτόματα το site σε κάθε αλλαγή στο repository. Όταν ολοκληρωθεί με επιτυχία το build, καταγράφεται στο Github Actions ως workflow run.

- Χρήση του workflow_run για συγχρονισμένη παραγωγή PDF

  Δημιουργήθηκε ένα δεύτερο Github Actions workflow που ενεργοποιείται μόνο όταν ολοκληρωθεί επιτυχώς το Pages build:

  ```
  on:
    workflow_run:
      workflows: ['pages-build-deployment']
      types: [completed]
  ```

  Έτσι, εξασφαλίζεται ότι το PDF δημιουργείται μόνο αφού έχει ενημερωθεί το site.

- Αποφυγή Infinite Loop

  Για να αποτραπεί το φαινόμενο infinite loop (το οποίο προκαλείται όταν το bot κάνει commit το παραγόμενο PDF και πυροδοτεί νέο Pages build), στο workflow προστέθηκε συνθήκη ώστε να παραλείπεται η εκτέλεση αν το τελευταίο commit έχει μήνυμα Update CV PDF (auto).
  Με τη χρήση του contains(github.event.workflow_run.head_commit.message, 'Update CV PDF (auto)') το σύστημα αναγνωρίζει τα auto-commits του bot και δεν επανεκκινεί το pipeline. Έτσι το PDF παράγεται μόνο όταν υπάρχουν πραγματικές αλλαγές στα δεδομένα.

  ```
  if: |
  github.event.workflow_run.conclusion == 'success' &&
  !contains(github.event.workflow_run.head_commit.message, 'Update CV PDF (auto)')
  ```

- Αυτόματο commit του PDF στο repository

  Το workflow, αφού δημιουργήσει το νεό PDF, το αποθηκεύει στο φάκελo assets/ και πραγματοποιεί commit αυτόματα:

  ```
  git add assets/cv.pdf
  git commit -m "Update CV PDF (auto)"
  git push
  ```

  Το PDF είναι πλέον διαθέσιμο στο site μέσω απλού link.

## Συμμετοχικό περιεχόμενο 3Β

Η εργασία πραγματοποιήθηκε σε περιβάλλον Windows, μέσω Git Bash. Αρχικά, παρουσιάστηκε σύγχυση ως προς τη χρήση εργαλείων όπως το latexmk και το tlmgr, τα οποία δεν ήταν διαθέσιμα στο περιβάλλον του Git Bash. Το πρόβλημα επιλύθηκε με την εγκατάσταση και χρήση του MikTeX, ο οποίος παρέχει το απαραίτητο σύνολο εργαλείων για τη μεταγλώττιση LaTeX εγγράφων στα Windows.

### Προβλήματα

Κατά τη διαδικασία παραγωγής του PDF παρουσιάστηκαν αρκετά τεχνικά προβλήματα, κυρίως λόγω της σύνθετης αλληλεπίδρασης Pandoc-LaTeX:

1. Μη εμφάνιση του κύριου περιεχομένου <br>
   Αρχικά, το παραγόμενο PDF περιείχε μόνο το front matter (τίτλος, copyright), χωρίς τα κεφαλαία. Το πρόβλημα εντοπίστηκε στον τρόπο που γινόταν η ενσωμάτωση των αρχείων (\include) και επιβεβαιώθηκε ότι τα αρχεία κεφαλαίων υπήρχαν και ήταν σωστά παραγόμενα σε .tex
1. Σφάλματα σε εικόνες και αναφορές σε figures <br>
   Εμφανίστηκαν προειδοποιήσεις και σφάλματα σχετικά με αρχεία εικόνων που δεν υπήρχαν (π.χ. αναφορές σε .md αρχεία ως εικόνες). Αυτό οφειλόταν σε Pandoc Lua φίλτρα που χρησιμοποιήσουσαν αρχεία Markdown ως ενδιάμεσες περιγραφές εικόνων (metadata). Όπου το αντίστοιχο αρχείο έλειπε, η μεταγλώττιση αποτύγχανε.
1. Απροσδιόριστες εντολές και περιβάλλοντα (CSLReferences) <br>
   Κατά την παραγωγή της βιβλιογραφίας εμφανίστηκαν σφάλματα όπως
   - Environment CSLReferences undefined
   - Lonely \item <br>
     Τα σφάλματα αυτά προέκυψαν επειδή το Pandoc παράγει LaTeX κώδικα για τη βιβλιογραφία που βασίζεται σε συγκεκριμένα περιβάλλοντα (CSLReferences) και μακροεντολές (\citeproctext), τα οποία δεν υπήρχαν. Το πρόβλημα λύθηκε με την προσθήκη των αντίστοιχων ορισμών στο preamble σύμφωνα με τις απαιτήσεις του Pandoc citeproc.
1. Ζητήματα υπερσυνδέσμων και επαναμεταγλώττισης <br>
   Εμφανίστηκαν προειδοποιήσεις του hyperref (π.χ. Rerun to get /PageLabels entry), οι οποίες σχετίζονται με την ανάγκη πολλαπλών μεταγλωττίσεων.

## Τελική Αναφορά

Έμεινα πολύ ικανοποιημένος από τον τρόπο που ήταν οργανωμένο το μάθημα. Οι οδηγίες ήταν ξεκάθαρες - αν και σε ορισμένες φορές αχρείαστα εκτενής - και βοήθησαν αρκετά ώστε οι εργασίες να γίνουν πιο εύκολα. Μέσα από τη διαδικασία ένιωσα ότι βελτιώθηκα αρκετά και πλέον έχω περισσότερη αυτοπεποίθηση όταν αντιμετωπίζω δυσκολίες.

Η ομαδική εργασία ήταν σημαντικό κομμάτι της εμπειρίας, καθώς συνεργαστήκαμε καλά και καταφέραμε να ολοκληρώσουμε το project. Πολλά από τα θέματα ήταν καινούργια για μένα, αλλά μέσα από την προσπάθεια κατάλαβα ότι με χρόνο και εξάσκηση υπάρχει πρόοδος.

Σαν αρνητικό θα έλεγα ότι ο τρόπος διεξαγωγής του μαθήματος ίσως χρειάζεται λίγο χρόνο προσαρμογής στην αρχή, ειδικά για όσους τον συναντούν πρώτη φορά. Επίσης, η συμμετοχή στις συζητήσεις δεν φαίνεται πάντα πλήρως, αφού συχνά χρησιμοποιούνται άλλα, πιο άμεσα κανάλια επικοινωνίας μεταξύ των φοιτητών.
